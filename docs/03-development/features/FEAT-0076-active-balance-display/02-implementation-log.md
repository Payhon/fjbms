## 实现结果

- 已先完成规格与设计，再实现移动端改动。用户确认不增加独立均衡状态查询。
- 核对同批工作表：`0x136` 高字节单位为 `0.1A/bit`，`0F FF` 为 `1.5A`；零值按详细案例与需求流程处理为有效主动均衡板，不采用通用备注中的“0 无效”。
- `readAllStatus()` 每轮先单独读 `0x136`；失败仅记录调试信息，随后继续正常状态读取。取消在可选查询前后都生效。
- 新增可选 `cell.balanceCurrentA`，仅从真实查询回复解析；不使用状态拼接区的零占位，原 `customStatus` 语义不变。
- 仪表盘在充放电开关下方始终显示完整均衡行，开关直接使用返回的均衡位；仅有效主动均衡电流显示一位小数。电芯背景仍由正电流与对应均衡位共同决定。
- 原 `0x11B/0x11C` 均衡数组与最高/最低电压文字颜色保持原逻辑。零电流、非主动板、查询失败、旧快照缺字段均不会残留均衡背景。
- 蓝牙完整快照上报指纹加入均衡电流和位数组，变化时通过原上报流程更新；MQTT 完整交互快照自然携带可选字段。
- 新增协议断言和实际 SFC 编译/渲染断言，无新依赖、权限或配置。

## 2026-10-17 仪表盘均衡行缺失修正

用户反馈充放电开关下方缺少均衡状态行。检查确认模板存在，但旧 `v-if="balanceCurrentA !== null"` 会在电流查询失败、不支持或快照缺字段时移除整行；旧开关计算也额外依赖正电流。

将条件移到电流文本，均衡行固定可见并占据完整下一行，开关恢复直接使用状态查询里的均衡位。仅调整仪表盘与对应测试，不改变电芯主动均衡门槛和协议请求，不触碰同期蓝牙重连进度修改。
