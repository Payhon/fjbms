## 1. 方案概览

在既有 `discoverWithAdvAbortable` 收到广播时用 `pickCandidate` 判定；匹配后唤醒等待，仍执行原 finally 的停止扫描、注销事件和归还租约。250ms 取消检查及各阶段超时保留。

## 2. 接口与数据结构

BLE 连接增加可选阶段回调，值为 `searching / connecting / initializing`。缓存层共享连接任务携带当前阶段和监听集合，后来加入者先同步当前阶段，返回后移除自己的监听。原调用者不传回调时保持原行为。

## 3. 关键流程

扫描成功启动后通知 searching，准备调用原生连接时通知 connecting，物理连接成功后通知 initializing；后续服务发现、通知订阅、稳定等待与单次校时不改变。详情回调校验当前数据会话与本次连接序号；顶部与遮罩复用同一计算文案。新会话和每次连接重置阶段。

## 4. 安全与权限

继续复用原设备匹配、连接关闭屏障和 OTA 独占保护；不更改权限、数据上报或协议帧。回调异常隔离，不中断连接。

## 5. 测试策略

模拟原生蓝牙 API，运行实际扫描/缓存/transport 代码验证命中提前退出及阶段通知；检查共享任务、取消、异常释放和页面生命周期。运行既有 BLE 缓存、校时、传输取消、仪表恢复、OTA、数据仲裁与主动均衡回归，以及类型和平台分支编译。

## 6. 兼容性与迁移

可选回调兼容原有调用者。微信小程序、Android、iOS 使用现有 uni API；不改连接平台分支及初次配网路径。无数据迁移。
