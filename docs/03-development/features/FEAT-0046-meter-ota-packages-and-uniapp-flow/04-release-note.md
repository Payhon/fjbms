- 三条BLE OTA在Boot结束后重建连接并读取实际设备响应/版本，升级与恢复结果分开；失败可手动重连，原生关闭无法确认时需重新进入小程序。

## 1. 本次变更
- OTA 升级包管理新增 `BMS 升级包 / 仪表升级包` 双 TAB。
- 新增仪表升级包类型，后台可单独上传和维护仪表固件。
- UniApp 蓝牙仪表详情页新增“仪表升级”卡片，支持手动选择仪表固件并直接升级。
- UniApp 蓝牙仪表详情页新增独立“BMS升级”卡片：读取现场BMS UUID/型号并匹配后台BMS包，通过仪表透传向 `0x01` 执行标准保护板OTA。
- 透传BMS升级只在点击后读取身份和检查固件；未检测到BMS时入口可见但禁用，UUID读取失败可按型号和版本降级匹配。
- BMS目标地址改为由升级对象显式指定，避免把仪表连接类型误当成升级对象；仪表自身仍为 `0xFC`，直接BMS和透传BMS均为 `0x01`。
- 修复 Android 仪表扫描进入详情可能连接到历史 AC 设备的问题。
- 修复 Android BLE 连接 API 不回调时详情页长期停留在“连接中”的问题。
- Android仪表OTA保持Boot帧单次BLE写入；数据阶段按设备ACK游标推进，每确认4KB后等待300ms再发送下一页首包。
- 优化蓝牙扫描页停止与超时体验：停止后不再处理过期设备发现回调，扫描超时后自动停止动画并恢复“开始扫描”按钮。
- iOS仪表OTA同样使用连续ACK窗口、同包重发与4KB页保护，结束后恢复原普通通讯参数。
- 防止微信小程序仪表OTA误报成功：全部数据必须由设备确认到 `requested == packetTotal`，再等待300ms发送真实固件CRC32的 `0x54`；末包缺ACK不得进入完成阶段，不能将发送完毕当成成功。
- 提升蓝牙BMS与蓝牙仪表OTA完成阶段稳定性：对齐旧版小程序经验，`0x54` 完成指令会在短时间内补发多次，真实 `status=0` 仍是首选成功证据；仅直连BMS/仪表自身保留下一条所述的完成后明确断连兼容，仪表透传BMS不适用。仪表额外兼容 `0xFD` Boot回包源地址。
- 蓝牙BMS与仪表均保留严格数据确认；完成阶段只为直连BMS或仪表自身BLE在全部数据ACK后、至少派发过一次 `0x54` 且出现明确原生设备断连的重启场景保留窄化兼容。仪表透传BMS、普通超时、数据未完整、非零状态及MQTT/4G断连仍失败；仪表专用地址、广播查询、跳过 `0x51` 和9600准备参数不变。
- BLE与MQTT/4G数据阶段均设置 `minFrameIntervalMs=0`、`packetDelayMs=0`，普通包由ACK直接驱动且无额外固定等待。两类链路均在每个已确认的4KB页边界等待300ms，再发送下一页首包，结束后恢复普通通讯原间隔。
- 优化蓝牙 OTA 启动等待：BMS 与仪表开始升级时会取消遗留状态读取并独占 BLE 请求队列，避免 Boot `0x50` 排队等待普通状态请求超时。
- 优化蓝牙 OTA 完成等待：BMS 与仪表在单个 6400ms 窗口内发送最多8次 `0x54`，首发后每隔800ms补发，发送时刻为 `0/800/1600/2400/3200/4000/4800/5600ms`；禁用额外 finalize 轮次与 iOS 替代写重试。收到 `status=0` 立即停止补发并成功，非零状态立即停止并提示设备拒绝，超时或断开不会误报成功。
- 调整全部移动端OTA数据时序：有效 `0x52` ACK后立即首发；BLE与MQTT/4G的 `0x50`～`0x53` 应答450ms，`0x53` 另保留220ms连续宽限。首包、中途、末包满670ms无ACK时重发同一包，不再跳到下一包。
- 设备返回的合法 `requested` 是唯一下一包游标，主机不以本地发送次数推断设备已写入；`status=3` 同样按设备游标有界恢复。ACK超时不伪造确认进度，真实写失败、断连、取消和明确拒绝仍报错。9月3日超时跳包/数据ACK不完整试验已由页边界失败日志证伪并撤销。
- Android特征明确支持 `write` 时，Boot帧显式采用带响应写，即使同时支持 `writeNoResponse`；仅不支持响应写时使用无响应写。两项能力明确false时Boot前失败，属性均缺失以 `legacy-unknown` 兼容旧运行时；响应写仅在同帧收到 `10007` 时回退一次。
- Android原生写回调只用于诊断，不代替Boot ACK；ACK仍是唯一协议成功证据。通知特征明确可读时，`0x53` 在450ms无ACK处增加一次best-effort读取以恢复Notify丢失，总窗口仍严格为670ms。超时日志补齐原生结果、回调耗时、RX字节数和限量解析错误，正常包日志不扩张。
- OTA期间BLE与MQTT均暂停普通轮询并独占请求队列，结束后恢复；进度由有效ACK推进，屏幕常亮在finally恢复，继续严格要求真实 `0x54 status=0`。
- Boot期间日志改为最近6000条内存追加，每个 `0x53` 数据包保留一条包含 `seq/status/requested/RTT` 的紧凑结构化 ACK；删除 Boot 层重复的 `0x53` 完整十六进制记录，完整十六进制只保留首包、末包、4KB边界包、同包重试和异常。结束集中保存和刷新列表，避免逐包同步全量存储影响时序。复制可取得当前内存日志；强杀进程可能丢失尚未保存的末段日志。
- 优化 iOS 从蓝牙扫描页进入仪表详情的首连耗时：扫描页 UUID 型 `deviceId` 可直接作为连接候选，主动取消旧连接后不再长时间等待旧连接锁。
- 开发者模式下新增仪表 OTA 端上调试日志，可在参数页直接查看并复制，便于排查用户环境下连接、下载、`0x50/0x52` 前置失败。
- 优化微信小程序主包体积：仪表 OTA 调试日志模块移入设备详情分包，并移除未引用的静态 `moment.js`。
- `0x53` 回包 `status=5` 统一提示为固件包大小与设备不一致。
