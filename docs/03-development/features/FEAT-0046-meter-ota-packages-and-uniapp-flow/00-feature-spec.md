# FEAT-0046 仪表 OTA 升级包与 UniApp 独立升级链路 - 功能规格

- status: in_progress
- owner: payhon
- last_updated: 2026-09-02
- related_feature: FEAT-0046
- version: v0.1.2

## 1. 背景与目标
- 当前 OTA 升级包管理与 UniApp 升级入口均围绕 BMS 设备设计，蓝牙仪表虽然走 Boot OTA 协议，但缺少独立的升级包管理和手动选包升级链路。
- 本次目标：
  1. 在 `ota_upgrade_packages` 中引入 `device_kind`，支持同表管理 BMS / 仪表升级包。
  2. 后台升级包管理页改为双 TAB，仪表升级包使用精简字段。
  3. UniApp 在蓝牙仪表详情页隐藏原 BMS OTA 检测入口，改为仪表专用“选包后升级”流程。
  4. 蓝牙仪表已透传连接 BMS 时，提供独立 BMS 升级入口，按现场 BMS 身份匹配后台固件并以 `0x01` 地址直接升级保护板。

## 2. 范围
### In Scope
- `backend/sql/51.sql` 为 OTA 升级包增加 `device_kind` 字段。
- `/api/v1/ota/package` 支持 `device_kind` 读写与分页过滤。
- 新增 `/api/v1/app/battery/ota/meter-packages` 返回仪表升级包全量列表。
- 后台 `升级包管理` 页面改为 `BMS 升级包 / 仪表升级包` 双 TAB。
- UniApp 设备详情参数页新增“仪表升级”卡片，仪表升级走手动选包 + `0xFC` Boot OTA。
- UniApp 仪表会话新增独立“BMS升级”卡片；点击后读取 BMS UUID，失败时按硬件型号降级匹配，并复用现有 BMS OTA 检查接口。
- 仪表透传 BMS OTA 固定使用 `0x01`，不使用仪表自身 OTA 的广播查询、跳过 `0x51` 或专用写包节奏。

### Out of Scope
- 不改 OTA 分包、CRC、Boot 帧格式。
- 不对仪表升级包做型号匹配或版本比较。
- 不新增第二张仪表升级包表。

## 3. 验收标准
1. `ota_upgrade_packages.device_kind` 可区分 BMS(`1`) 与仪表(`2`) 包。
2. 后台升级包管理页可按 TAB 分别管理 BMS 与仪表包；仪表表单仅包含名称、文件、说明。
3. `/api/v1/app/battery/ota/meter-packages` 仅返回当前租户仪表升级包的 `id/name/description/package_url`。
4. UniApp 蓝牙仪表详情页隐藏旧 OTA Cell 与红点，显示“仪表升级”卡片。
5. 用户选择仪表固件并确认后，升级直接下载所选固件并按 `0xFC` 目标地址执行。
6. 蓝牙已连接但仪表尚未与后端 BMS 建立透传时，设备详情状态区可为空，前端不应无限重试读取状态；该场景仍须允许仪表升级。
7. BMS 升级卡片仅在蓝牙仪表会话显示；未读到 BMS 型号和版本时显示但禁用。
8. 点击 BMS 升级后才读取 UUID 和请求升级包，不在页面加载时新增 BLE/网络请求。
9. UUID、型号、批次约束沿用现有 BMS 选包优先级，并允许无约束通用 BMS 包兜底；所有查询受当前租户隔离。
10. 仪表透传 BMS 的首个 Boot 查询帧为 `55 FE 01 50 00 00 0C 39 FD`，后续流程与直接连接保护板一致。
11. 仪表自身、仪表透传 BMS、直接连接 BMS 三条链路均只有收到真实 `0x54 status=0` 才显示升级成功。
12. 全部移动端 OTA 链路在有效 `0x52` 应答后 `300ms` 发送首个 `0x53`；BLE 与 MQTT/4G 的 `0x50`～`0x53` 单次应答超时统一为 `600ms`，非 `0x54` 的 ACK 后主动等待不得超过 `700ms`；最后一个 `0x53` ACK 后 `300ms` 发送首个 `0x54`。BLE 在等待应答期间每隔 `800ms` 补发一次，总计最多发送 8 次（`0/800/1600/2400/3200/4000/4800/5600ms`），单个应答窗口为 `6400ms`；MQTT/4G 保持单次发送和 `5s` 应答窗口。
13. BLE 收到匹配的 `0x54 status=0` 后立即成功并取消剩余补发；收到非零状态立即按设备拒绝失败并取消剩余补发；窗口超时后不再开启第二轮 finalize。

## 4. 风险与约束
- 仪表包与 BMS 包同表存储，历史 BMS 字段约束仍存在，因此仪表包需在服务层自动填充兼容值。
- 仪表升级包列表按租户全量返回，若同租户仪表固件较多，移动端选择体验依赖命名规范。
- 仪表临时会话没有可信 `device_id`；BMS 固件匹配必须使用现场 UUID/型号，禁止伪造设备ID或放宽租户边界。
- 新硬件 ACK 后主动等待仍受 `700ms` 时序约束；本轮按客户验证方案将 BLE 与 MQTT/4G 非完成帧应答窗口统一调整为 `600ms`，若旧 Bootloader 无法按该窗口 ACK，或超时后不能安全处理同帧重发，必须通过真机日志识别并继续调整或回滚。

## 5. 回滚方案
- 回滚 `device_kind` 相关服务与前端调用。
- UniApp 回滚至现有 BMS OTA 入口逻辑，取消仪表升级卡片。
- 透传 BMS OTA 可独立回滚其卡片、身份解析与后端无 `device_id` 匹配分支，不影响仪表自身和直接连接 BMS OTA。
- 文档与看板状态同步回退。
