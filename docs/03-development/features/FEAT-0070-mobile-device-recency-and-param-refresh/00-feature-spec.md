# FEAT-0070 移动端设备最近连接排序与参数刷新 - 功能规格

- status: review
- owner: payhon
- last_updated: 2026-07-25
- related_feature: FEAT-0070
- version: v0.1.0

## 1. 背景与目标
- 移动端首页对 4G BMS 离线设备显示“4G 离线”角标，列表密集时形成无效视觉噪声。
- 首页设备列表当前按绑定或添加时间排序，无法优先呈现最近成功通讯的设备。
- 参数设置基础分组首次读取后会使用已加载缓存；首次返回空数据或后续需要重读时缺少显式刷新入口。
- 本次目标：
  1. 4G BMS 离线时隐藏状态角标，在线时继续显示“4G 在线”。
  2. 首页三种视图按设备最近一次成功通讯时间稳定倒序分页。
  3. 为单体、总压、电流、温度四个基础参数分组增加显式刷新。

## 2. 范围
### In Scope
- UniApp 首页设备卡片 4G 离线状态展示优化。
- 后端记录设备级最近成功通讯时间，并调整 APP 首页设备列表排序。
- BLE 成功连接上报和 4G 非 retained 真实回包更新连接时间。
- UniApp 参数基础分组刷新按钮、加载反馈、重复请求保护和失败值保护。
- 中英文提示、数据库增量、基线 SQL、自动化测试、文档和看板。

### Out of Scope
- 不改变 `is_online` 在线判定规则、TTL 或 4G/BLE 协议。
- 不因打开详情页、断开、失败请求或 retained 回包更新连接时间。
- 不修改首页列表接口请求或响应结构。
- 不调整高级参数弹层、参数写入、OTA 或 30 秒 MQTT 保活策略。

## 3. 验收标准
1. `bms_comm_type=2/3` 且离线的设备不显示任何状态角标，并释放标题右侧空间；在线时显示绿色“4G 在线”。
2. BLE、普通 MQTT 和非 4G 离线设备保持现有状态展示。
3. BLE 成功连接上报和 4G 真实非 retained 回包使用服务端时间更新 `devices.last_connected_at`。
4. 三种首页视图按 `last_connected_at` 倒序；空值按原绑定/添加时间倒序；同时间按设备 ID 稳定排序。
5. 四个基础参数分组展开后，折叠图标左侧显示可点击刷新图标，点击不折叠分组。
6. 刷新绕过已加载缓存，加载中禁止重复请求并展示旋转反馈。
7. 读取至少一个允许参数值才算成功；失败不清空旧值、不折叠分组，并显示中英文失败提示。

## 4. 风险与约束
- 新字段需要先执行数据库增量再发布读取该字段的后端。
- 最近成功通讯时间是设备级全局口径，不区分发起连接的账号或手机。
- 4G 回包更新时间沿用现有 Socket 在线刷新节流，避免高频写库。
- 参数读取继续复用共享串行 Transport，刷新不得并发插入第二个同组请求。

## 5. 回滚
- 回滚 UniApp 卡片和参数刷新交互。
- 回滚首页排序为原绑定/添加时间顺序。
- `last_connected_at` 字段可保留为空闲兼容字段；若必须移除，确认旧后端已回滚后再单独删除。
