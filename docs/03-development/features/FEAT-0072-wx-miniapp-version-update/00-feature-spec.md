# FEAT-0072 微信小程序版本更新检测 - 功能规格

- status: review
- owner: payhon
- last_updated: 2026-08-13
- related_feature: FEAT-0072
- version: v0.1.0

## 1. 背景与目标

- 微信小程序发布新版本后，现有移动端没有显式提示，用户可能继续运行微信缓存的旧版本。
- 目标是在用户下一次进入微信小程序时使用微信原生更新机制检测版本；新版本下载完成后弹出提示，用户确认后自动应用更新并重启小程序。

## 2. 范围

### In Scope

- 微信小程序应用启动时初始化 `UpdateManager`。
- 监听新版本检测、下载完成和下载失败事件。
- 新版本可用且下载完成后显示不可取消的更新提示，点击确认后调用 `applyUpdate()`。
- 新版本在小程序位于后台时下载完成，则在用户再次进入前台时提示。
- 补充中英文提示文案、自动化断言和项目看板。

### Out of Scope

- 不改变 Android/iOS App 现有自建升级中心。
- 不由业务后端维护或比较微信小程序版本号。
- 不绕过微信平台的版本发布、灰度和下载调度机制。
- 不在没有新版本时打扰用户。

## 3. 用户价值

- 用户重新进入小程序即可获得微信平台已发布的新版本提示。
- 用户只需点击一次确认，小程序自动更新并重启，无需清缓存或重新搜索小程序。

## 4. 验收标准

1. 仅微信小程序编译目标启用版本更新检测，App/H5 行为不变。
2. 小程序启动时只注册一组更新监听器，重复 `onShow` 不重复绑定。
3. 没有新版本时不显示弹窗。
4. 新版本下载完成且小程序处于前台时，显示“发现新版本”提示，弹窗不提供取消按钮。
5. 用户点击确认后调用 `UpdateManager.applyUpdate()`，由微信自动重启到新版本。
6. 新版本在后台下载完成时不抢占后台界面；用户再次进入前台后立即提示。
7. 更新包下载失败时显示明确提示，用户可在检查网络后重新进入小程序触发下一次检查。
8. 更新检测或提示异常不得阻断登录、首页加载及已有 App 端升级流程。

## 5. 风险与约束

- 是否检测到新版本、下载时机和灰度范围由微信平台控制，业务代码不能主动指定版本或强制立即下载。
- `applyUpdate()` 只能在更新包下载完成后调用，因此提示在 `onUpdateReady` 后展示。
- 真机或体验版验证需要在微信公众平台实际发布高于当前运行版本的新版本；开发工具静态检查不能替代此项验收。

## 6. 回滚方案

- 回滚 `App.vue` 的微信小程序生命周期接入、更新控制器、中英文文案及测试文件即可恢复原启动流程。
- App 端现有升级逻辑与本功能隔离，无需回滚。
