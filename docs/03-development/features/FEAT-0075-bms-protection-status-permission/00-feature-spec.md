# FEAT-0075 BMS 保护状态整块显示权限

- status: review
- owner: payhon
- last_updated: 2026-09-28
- related_feature: FEAT-0075
- version: v0.1.0

## 1. 背景与目标

仪表盘的“BMS保护状态”目前固定显示。后台需提供一个权限项，统一控制微信小程序、Android/iOS App 和 Web 的整个保护状态区块。

用户已确认：只有明确授权才显示；权限未加载、空权限、未授权和请求失败均隐藏。后台保存后，重新进入详情或刷新页面生效。

## 2. 范围

- 系统管理 → 权限管理 → 移动端权限新增“BMS保护状态”，编码 `app_device_detail_protection_status`，移动端与 Web 共用。
- 整块控制标题、摘要、展开/收起按钮及所有 ON/OFF 行；Web 隐藏时移除整个网格项。
- 沿用当前机构类型规则：终端用户读取 `APP_USER`；机构用户只读取所属机构类型配置。
- 新增幂等 `backend/sql/67.sql`，同步初始化 `backend/sql/1.sql`，确保移动端权限根节点存在并注册新节点，不给已有机构或用户自动授权。
- 移动端复用详情页当前权限请求，同时解析历史记录和保护状态权限；Web 使用同一现有接口。
- 保留顶部故障、告警、保护提示与历史记录权限行为，不调整设备通信、协议、连接或数据读取。
- 实现阶段不包含提交、推送、数据库部署或客户端发布。2026-09-28 用户追加授权将 SQL 和后台前后端更新至生产与测试；移动端客户端发布仍不在范围内。

## 3. 用户价值

管理员按机构类型决定是否展示保护明细，所有客户端遵循同一配置；用户进入页面时不会先看到尚未获准的区块。

## 4. 验收标准

1. 授权后重新进入详情，完整区块可显示并可展开/收起；取消后重新进入，完整区块隐藏。
2. 未授权、空权限、加载中和请求失败时隐藏，无首屏闪现；两端显隐一致。
3. `APP_USER` 与机构类型配置互不借用；现有历史记录权限独立生效。
4. 迁移重复执行不产生重复节点，不改变已有授权；初始化 SQL 注册同一节点。
5. 完成页面行为测试、UniApp 类型/SFC 检查和微信小程序编译，以及 Web 显式类型检查、受影响文件 ESLint 和构建；结果及既有阻塞分别记录。
6. 浏览器后台勾选/取消、重新进入详情及微信小程序、Android/iOS 真机验收分别记录；真机验收未完成前保持 `review`，不标记 `done`。

## 5. 风险与约束

- 这是展示权限，不改变保护数据采集和设备保护功能。
- 客户端更新后，已有账号默认隐藏；需管理员明确勾选授权。
- 发布顺序为先注册数据库节点，再更新客户端；不增加接口、全局状态或运行中刷新机制。
- 保留工作区原有未提交修改；编译及隔离测试不作为真实环境验收证据。
- 部署核对发现当前后端已包含 2026-09-24 发布生产的绑定名称修复（FEAT-0013）。为保留已上线行为，使用当前后端构建产物；生产已存在 SQL 66 的列，测试环境先补 SQL 66，再执行 SQL 67。本次不向已有账号自动授权保护状态。

## 6. 回滚方案

回退本次两端显隐改动即可恢复原展示行为。注册的权限节点可保留；若需移除，先备份并仅清理本功能节点及其授权编码，保留移动端权限根节点和历史记录节点。2026-09-28 已按追加授权更新生产与测试 SQL、后台前后端；具体结果、备份与测试 MQTT 阻塞见测试报告和发布说明，本次未执行回滚。
