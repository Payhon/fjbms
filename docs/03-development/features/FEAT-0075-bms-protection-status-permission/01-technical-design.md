## 1. 方案与接口

复用 `GET /api/v1/org_type_permissions/mobile_ui_codes/me` 及原有 `ui_codes` 响应。仅当数组包含 `app_device_detail_protection_status` 时显示；不使用 `allow_all` 放开该区块。

后台权限管理按数据库 UI 元素树展示“移动端权限”，现有保存接口持久化 `ui_codes`，无需修改权限管理页面或后端接口。当前服务端逻辑已将终端用户映射到 `APP_USER`、机构用户映射到自己的机构类型，并只返回移动端权限根节点下的编码。

## 2. 移动端

`pages/device-battery/detail.vue` 将历史记录权限加载函数改为 `loadDetailUIPermissions`，同一请求更新历史记录与保护状态的两个布尔值。初始值和请求开始时均为 `false`，失败保持隐藏；复用页面生命周期代次，丢弃卸载后的延迟响应。

`dashboard-tab.vue` 接收 `showProtectionStatus: boolean`，在最外层 `protect-card` 上使用 `v-if`。标题、摘要、展开按钮和所有状态行一起移除。微信小程序、Android/iOS 使用同一页面和组件逻辑。

## 3. Web

`src/service/api/org-type-permissions.ts` 增加现有接口的类型化封装。BMS 面板挂载时请求权限，初始、加载和失败时为 `false`；明确授权后才显示。在保护卡片的整个 `NGridItem` 上使用 `v-if`，隐藏后不保留空网格项。

后台保存后在新一次详情挂载或页面刷新时重新获取。不增加轮询、权限缓存或全局状态。顶部故障/告警/保护提示及现有设备参数权限保持原逻辑。

## 4. 数据库注册

`67.sql` 创建缺失的 `app_mobile_permissions` 根节点，并按现有根节点 ID 注册保护状态叶节点（类型 4，排序 19992，编码与 param1 一致）。按编码判重，重复执行可校正新叶节点的展示元数据；不改现有根节点、历史记录节点和机构授权数据。

`1.sql` 末尾同步完全相同的注册块。新节点默认不授权。生产发布需先执行 SQL 67，再更新客户端，由管理员明确勾选。

## 5. 验证与回滚

使用两端真实权限加载函数和卡片模板进行隔离行为检查，覆盖授权、拒绝、空值、失败、延迟及历史记录独立性。使用现有后端测试数据库验证机构类型隔离；使用独立 PostgreSQL 容器验证迁移和初始化注册块的重复执行。

分别记录类型/SFC/构建、隔离浏览器与真实后台/真机验收。回滚客户端改动可恢复原展示，权限节点可保留；删除节点时不得删除共用根节点或历史记录权限。

## 6. 2026-09-28 部署执行

使用现有 `scripts/devops.py` 的 SSH、二进制更新和 Web 备份替换流程。部署前冻结分别按测试/生产构建的 Web 产物和 Linux/amd64 后端产物；只上传指定迁移，保留目标环境配置文件。

SQL 使用 `ON_ERROR_STOP` 和事务执行，并在事务内断言原有机构授权、设备绑定数据不变及新节点唯一。测试先补生产已有的 SQL 66，再执行 SQL 67；生产只执行 SQL 67。保留权限相关表的 PostgreSQL 自定义格式备份、旧二进制和旧 Web 归档，并校验 SHA-256。

生产后端与冻结产物完全一致，保留原进程；新权限树直接读取数据库，无需为节点注册重启后端。测试后端已替换并重启，但其既有 MQTT 配置指向 pbsmart 的 Broker（`127.0.0.1:1883`），认证回调为 `http://java:8080/iot/tool/mqtt/authv5`。MQTT 连接被拒绝后启动流程一直重试，HTTP 尚未启动。该环境依赖阻塞单独记录，不作为本次权限实现或生产健康检查失败。
