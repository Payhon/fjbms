# FEAT-0052 UniApp 设备详情、扫描、多语言与登录体验优化 - 功能规格

- status: in_progress
- owner: payhon
- last_updated: 2026-09-28
- related_feature: FEAT-0052
- version: v0.1.0

## 1. 背景与目标
- 背景：
  - 移动端设备详情顶部仪表同时展示 SOC/SOH，不符合当前只突出 SOC 的展示要求。
  - 高级参数缺少只读 SOH 与虚拟容量写入能力。
  - BLE 扫描页信号格阈值偏保守，用户难以感知较好信号。
  - 英文语言下仍有参数项、微信小程序 Add Device 取消按钮等中文残留。
  - 未登录首次打开时多入口守卫可能连续跳转登录页。
  - 微信小程序登录/注册链路的用户协议与隐私政策勾选不得默认代用户同意。
  - 微信审核要求登录环节提供显著有效的取消、拒绝或返回入口；当前登录页使用自定义导航且无返回按钮，用户无法拒绝登录并继续访客体验。
  - 蓝牙仪表读取到后端 BMS 状态后，扫码提示框与顶部入口会同时隐藏，导致用户无法继续扫码切换仪表当前连接的 BMS 板。
  - 客户已习惯从底部“＋”进入蓝牙搜索后立即开始发现设备；完全手动启动增加了一次操作，但直接恢复每次 `onShow` 自动扫描会重新引入扫描过频和连接争用风险。
  - 蓝牙设备较多时，广播 RSSI 每次变化都会立即触发列表重排，设备名称位置持续跳动，用户难以在扫描过程中准确点击目标设备。
  - 扫码绑定 BMS 成功后，详情页断开蓝牙并返回扫描页时，页面会因目标已绑定而再次跳转详情并重新连接，违背用户的断开意图。
- 目标：
  1. 设备详情顶部仪表只显示 SOC，左右进度条均使用 SOC。
  2. 高级参数展示只读 SOH，并支持虚拟容量按 AH 写入；只读 SOH 与虚拟容量入口均受设备参数权限控制。
  3. 按新阈值优化 BLE 信号格显示。
  4. 补齐本次涉及页面与小程序自定义 TabBar 的中英文文案。
  5. 登录守卫增加节流，避免重复跳登录页。
  6. 微信小程序环境下登录页与注册设置密码页的协议勾选默认未选中，必须由用户主动选择。
  7. 仪表盘 SOC 保留整数位时直接截断小数，不使用四舍五入。
  8. 修复扫描中返回首页后立即再次进入蓝牙搜索时，首页自动连接与扫描页争用系统 BLE discovery、触发 `10008/-30008 scanning too frequently` 的问题。
  9. 蓝牙仪表读取到后端 BMS 状态后自动收起大提示框，同时保留顶部扫码入口，允许用户再次展开提示并扫码切换其他 BMS 板。
  10. 底部“＋ > 搜索”入口恢复一次性自动扫描，并将普通搜索缩短为 15 秒，同时保持既有扫描串行、退避和连接前清理保护。
  11. 将扫描列表位置重排限制为约每 2 秒一次，并在触摸或滚动期间暂停重排，使用户无需停止扫描即可准确选择设备。
  12. 微信小程序登录页增加顶部返回入口；有上一页时返回上一页，无上一页或返回失败时进入首页访客态。
  13. 扫码识别未绑定 BMS 的 MAC 后，蓝牙搜索页首次显示自动开始目标匹配，无需再次点击“开始扫描”。
  14. 扫描停止后重新点击“开始扫描”时自动清理上轮结果，无需先点击“清空列表”，避免旧 RSSI 排序和旧 MAC 干扰新一轮搜索。
  15. 同一次扫码只消费一次自动连接入口；从连接或绑定流程返回扫描页后保持停止态，重新连接由用户点击设备发起，新一次扫码仍可自动连接。

## 3. 验收标准
1. 仪表盘顶部只在中间展示一个 SOC 百分比与 SOC 文案，左右进度条均随 SOC 百分比变化。
2. 高级参数弹层可看到只读 SOH，值优先来自实时状态。
3. 只读 SOH 可在后台“系统管理 > 权限管理”的设备参数权限中通过 `10d` 节点配置，取消勾选后移动端高级参数不显示该值。
4. 虚拟容量入口可在后台“系统管理 > 权限管理”的设备参数权限中配置；输入 `50` 时按 `50000` 原始值写入 `0x0627~0x0628`，目标地址为 `0x00`。
5. BLE 扫描页 RSSI 信号格按 `-80/-85/-90/-95` 阈值显示。
6. 英文语言下参数页、Add Device 弹层取消按钮、“我的”语言菜单无本次已知中文残留。
7. 未登录首次打开或点击 Add Device 时只触发一次登录跳转；微信小程序切换英文后进入 Home，底部 TabBar 保持英文。
8. 首页蓝牙连接设备点击断开后单次操作即可更新为断开状态，不再要求二次点击。
9. 微信小程序登录页、注册设置密码页首次进入时协议勾选为空；未勾选时不能提交，用户手动勾选后可继续原登录/注册流程。
10. SOC 为 `77.5%` 时仪表盘显示 `77%`，不得四舍五入显示为 `78%`。
11. 扫描中返回首页并立即再次进入蓝牙搜索时，手动扫描、首页自动连接扫描与通用 BLE transport 扫描必须全局串行，任意时刻最多存在一个 discovery 所有者。
12. 页面 `onHide` 与 `onUnload` 的重复清理必须幂等；旧页面清理不得在新页面启动后关闭适配器或停止新扫描。
13. 仅蓝牙确实不可用（错误码 `10001`）时提示进入系统蓝牙设置；`10008/-30008` 必须按“扫描操作过于频繁”处理并只做一次退避重试，不得误提示蓝牙未开启。
14. “正在扫描”状态只能在 `startBluetoothDevicesDiscovery` 成功后展示；启动失败时不得产生虚假扫描状态。
15. 底部“＋ > 搜索”携带 `auto_start=1` 并在本次页面导航首次显示时自动启动一次；相机扫码匹配在 `mode=qr` 且具有合法目标 MAC 时同样自动启动一次，不要求额外参数；无标记普通直达保持手动，也不得将普通搜索标记为 `entry_source=scan`。
16. 普通 BLE 搜索（首次自动搜索及按钮重试）单次持续 15 秒；二维码目标匹配继续保持 30 秒。超时后保留已发现列表并恢复“开始扫描”按钮；再次启动新一轮扫描时自动清空旧结果及排序状态，仅展示本轮重新发现的设备。
17. 扫描过程中未点击“停止扫描”而直接离开页面时必须自动停止 discovery；切后台、进入系统设置或再次 `onShow` 均不得重新自动启动，用户可通过按钮手动重试。
18. 自动或手动启动搜索时，只取消首页尚未完成的临时自动连接并快速释放全局 BLE 租约；选择设备后必须先停止 discovery、释放租约再进入连接流程，不得断开已缓存的正常连接或详情页交互连接。
19. 蓝牙仪表会话读取到后端 BMS 状态后，大提示框必须自动收起，顶部断开连接旁的扫码入口必须显示；点击入口后应切换到仪表盘并重新展开提示框，用户可继续扫码切换其他 BMS。`allow_scan_handoff=0`、普通 BMS 直连和云端会话不得显示该入口。
20. BLE 广播中的名称、RSSI、MAC 和最后发现时间继续实时更新；已存在设备不得因单个广播包立即换位，列表重排间隔为 2,000ms。
21. 新发现设备必须立即追加到列表末尾，不挤动已有设备；下个排序周期再按二维码目标优先、RSSI 从强到弱归位，RSSI 相同或无效时保持上轮相对顺序。
22. 用户触摸或滚动列表时不得重排；`touchend/touchcancel` 后至少等待 600ms，并满足原 2 秒排序间隔后才能执行待排序任务。
23. 停止扫描或超时时，未触摸列表可立即执行最终排序；清空列表、页面隐藏、卸载或扫描 session 失效必须取消定时器和迟到排序任务。
24. 设备行继续以 `deviceId` 作为稳定 key 并保持整行可点击，不增加会移动点击目标的列表换位动画；扫描过程中点击设备仍须先停止 discovery、释放租约再连接。
25. 微信小程序普通账号登录与 PACK 微信登录专页均显示可用的顶部返回箭头；页面栈大于 1 时返回上一页，页面栈仅登录页或 `navigateBack` 失败时切换到首页，`switchTab` 失败再以 `reLaunch` 兜底。返回过程不得发起登录请求、授权弹窗或重复登录提示，非微信小程序端不得新增该入口。
26. 未绑定 BMS 扫码、匹配、绑定并进入详情后，无论主动断开再返回还是直接返回，扫描页均不得因目标变为已绑定而自动跳转详情、重新扫描或重新连接；重复显示及后台恢复同样保持停止态。
27. 当前扫码页自动匹配或手动选择过设备后，再次点击“开始扫描”只发现并更新设备列表，点击设备才继续连接；首次已绑定扫码仍直达详情，新导航实例可再次自动匹配，未选择设备时的扫描失败或超时仍可手动重试目标匹配。

## 4. 风险与约束
- 新一轮启动清理只影响扫描页临时列表，不解绑设备、不清空已绑定设备缓存、不主动断开 BLE。停止操作和同一轮内部无 Service 过滤降级不得清空已发现结果；启动失败后保持空列表和现有错误提示，用户可手动重试。
- 扫码自动启动复用共享页面策略，覆盖微信小程序底部 TabBar 与 UniApp 扫码入口；缺失或非法目标 MAC 不自动启动，已绑定设备仍优先直达详情。仪表直达、UUID 绑定、详情退出断连、首页 30 秒暖连接和二维码 4G 宽限均不改变。
- 绑定列表刷新完成后必须先检查页面可见性与代次，已失效的任务不得跳转或启动搜索；本次不调整列表请求与 BLE 启动的先后关系、不新增无限重试。
- 虚拟容量命令目标地址与普通参数写入不同，必须使用专用 targetAddress，避免影响默认 `0x01` 参数写入。
- 微信小程序原生 `showActionSheet` 取消按钮受宿主语言影响，因此本次使用自定义弹层。
- 登录守卫节流只抑制短时间重复导航，不能屏蔽用户后续主动进入登录页。
- 协议默认勾选调整仅限微信小程序编译目标，其他端保持现有默认勾选行为以降低变更面。
- 登录页返回入口仅在 `MP-WEIXIN` 编译目标渲染；首页已有未登录空态，作为无页面历史时的安全访客落点。
- BLE discovery 协调仅约束扫描资源，不改变设备名称/MAC/ServiceData 过滤、已绑定设备分流、连接协议、参数读写和 OTA 行为。
- `10008/-30008` 自动恢复最多重试一次，避免无限重试进一步触发系统频率限制。
- 一次性自动启动在首次 `onShow` 即消费；绑定列表刷新期间若页面隐藏或用户主动操作，迟到任务不得启动，后台恢复也不得补启。
- 已绑定目标的自动跳转与自动启动共用首次入口消费标记；自动匹配和手动选择共用页面已有的导航标记。标记仅属于当前扫描页实例，不新增跨页断开状态，不改变详情断连、首页暖连接、协议或 OTA 流程。
- 2 秒排序节流只约束设备行顺序，不降低广播接收、二维码目标匹配、信号图标更新或设备选择响应速度。
- 仪表扫码提示仅在 BMS 状态从“未读取”切换为“已读取”时自动收起，避免用户主动重新展开后被后续状态轮询反复关闭。

## 5. 回滚方案
- 2026-09-28 返回体验增量可单独回滚已绑定跳转的首次入口条件和手动选择时的导航标记，保留首次扫码自动搜索、BLE 租约与详情断连策略；回滚会恢复本次反馈的返回自动重连行为。
- 若新一轮自动清理体验不符合预期，仅移除 `startScan()` 内对 `clearList()` 的调用，保留扫码自动启动、稳定排序、全局租约与连接策略。
- 若扫码自动启动出现兼容问题，仅回滚入口策略中的二维码分支和对应页面入参，保留普通搜索一次性启动、全局租约、退出清理与详情连接策略。
- 回滚 FEAT-0052 涉及的 UniApp 改动、协议文档更新与看板登记。
- 若虚拟容量现场验证异常，优先禁用高级参数中的入口，保留受权限控制的只读 SOH 与展示优化。
- 若全局扫描协调在特定端出现兼容问题，可回滚协调器接入和错误分类改动，恢复原页面级扫描流程；不得回滚本功能目录内其他已交付能力。
- 若微信小程序登录页返回入口出现布局或路由兼容问题，可单独回滚该入口与返回处理，不影响登录、协议勾选及其他端行为。
